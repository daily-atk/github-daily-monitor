# 知乎日更模板

## 平台特点

- **想法**适合日更（300–500 字），**文章**适合周更（1500–2500 字，吃搜索流量）
- 允许外链；明确写“我是作者”，不要装路人
- 语气：比小红书更完整、更有逻辑；少 emoji，多分段
- 发布时间：20:00–22:00
- 话题：GitHub、开源、效率工具、Python、独立开发

## 标题公式（文章）

1. 有哪些适合普通人、不写代码也能用的 GitHub 项目？
2. 我做了个给普通人看的 GitHub 日报：每天筛出真正能用的项目
3. GitHub 上哪些项目普通人真的用得上？我做了个自动筛选器
4. 不写代码的人，怎么从 GitHub 找到真正有用的工具？

## 周更文章模板

```
# {标题}

## 为什么 GitHub Trending 不适合普通人

（写痛点：框架、SDK、自托管服务，普通人第一步就劝退。）

## 我想要的日报长什么样

一份合格的日报应该回答三个问题：
1. 这东西具体是干什么的？
2. 适合谁？手机还是电脑？要不要自己搭服务？
3. 免费吗？还在维护吗？

## 今日推荐

### 1. {项目名}

- 功能：{一句话}
- 适合谁：{人群}
- 平台 / 许可证：{平台} / {许可证}
- 注意：{注意事项}
- 链接：{GitHub 地址}

### 2. ...

（重复 3–5 个）

## 它是怎么筛的（可选，技术读者）

- 关键词轮换 + 核心词召回
- 本地短语校验（habit tracker 排除 habitat）
- 30 天推荐冷却 + 7 天见过冷却
- 每个领域最多 3 个
- 无许可证扣分

## 怎么用

- Windows 双击 `运行日报.bat`
- macOS/Linux 跑 `./run.sh`
- 也可以每天自动发布到 GitHub Pages

## 局限

- 启发式筛选，不是人工精选
- 不保证每天都有 10 个
- 不配置 AI 时文案偏模板化

## 链接

- 仓库：https://github.com/daily-atk/github-daily-monitor
- 日报：https://daily-atk.github.io/github-daily-monitor/
```

## 知乎排版建议

- 每段 2–4 行，避免大段文字
- 项目名用 **加粗**
- 许可证写清楚（MIT / Apache-2.0 / GPL-3.0），这是知乎读者会追问的点
- 文末放仓库和日报链接，并注明“我是作者”
- 文章发一次后，想法可以每天摘 3 条，形成持续曝光

## 发布检查

- [ ] 明确写出“我是作者”
- [ ] 每个项目有平台 + 许可证
- [ ] 至少一个项目是“手机/网页直接用”
- [ ] 文末有仓库链接和日报链接
- [ ] 没有“最好/第一/保证”这类绝对化表述
- [ ] 文章中段有分段标题，适合手机阅读

## 不要做

- 把小红书文案原样搬过来（太长、太口语）
- 在多个问题下复制同一个回答（容易被折叠）
- 只发链接不写内容
- 推荐自己没看过的项目
