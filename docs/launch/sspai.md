# 少数派发布文案

**标题**

把 GitHub 变成一份普通人能看的日报：一个零依赖小工具的诞生

**副标题**

自动筛选、30 天去重、领域配额，还能一键发布到 GitHub Pages

---

## 为什么普通人不需要 GitHub Trending

GitHub 上每天都有大量新项目，但「Trending」和大多数精选列表默认读者是开发者：框架、SDK、命令行工具、自托管服务。对不写代码的人来说，这些内容很难转化成「今天我能用什么」。

我想做的不是又一个开发者日报，而是一份**给普通人看的日报**：只关心学习、生活、效率、健康、财务，明确把开发者基础设施排除在外。

## 我想要的日报长什么样

一份合格的日报应该回答三个问题：

1. 这东西具体是干什么的？
2. 适合谁？手机还是电脑？要不要自己搭服务？
3. 免费吗？还在维护吗？

所以最终的报告里，每个项目都有：主要功能、适合人群、实用价值、平台、最近更新时间、许可证、注意事项。不是只列一个项目名和一句 README 标语。

## 它是怎么筛的

流程不复杂，但每一步都针对「普通人视角」：

- **采集**：用配置里的关键词搜索近期新建和近期有更新的项目。
- **过滤**：无描述、教程合集、SDK / library / framework、fork 比异常、体积过小的项目直接排除。
- **本地短语校验**：搜索用核心词保证召回，但结果必须包含配置短语里的实词。例如 `habit tracker` 会排除 `habitat`。
- **去重**：推荐过的项目 30 天内不再出现；只是见过但没选上的，冷却 7 天。
- **领域配额**：每个领域最多 3 个，避免整份日报被「生活」类刷屏。
- **打分排序**：消费级信号加分，开发者基础设施、无许可证项目扣分。

## 三种用法

1. **Windows**：双击 `运行日报.bat`，结束后自动打开 HTML 报告。
2. **macOS / Linux**：`chmod +x run.sh && ./run.sh`。
3. **全自动**：仓库自带 GitHub Actions，每天北京时间 20:00 运行并发布到 GitHub Pages，同时生成历史归档页。

## AI 是可选，不是必需

不配置任何 AI，脚本也能生成完整报告，只是文案会用规则兜底模板，比较笼统。

如果想要更具体的描述，可以接入任意 OpenAI 兼容接口：

```bash
export LLM_API_KEY="..."
export LLM_MODEL="deepseek-chat"
python enrich.py --dry-run
python enrich.py --enable --max-cost 0.05
```

默认关闭，不加 `--enable` 不会调用接口；`--dry-run` 可以先看 prompt 和预估费用。

## 局限与边界

- 筛选是启发式的，不是人工精选，质量会有波动。
- 「对普通人有价值」本身有主观性，欢迎用 issue 告诉我哪些项目不该被推。
- 不保证每天都有 10 个，宁缺毋滥。
- 只聚合公开信息，不自动安装任何项目；使用前请自行查看许可证和 Issue。
