## 1. 定位、目标用户、核心卖点

### 1.1 项目定位（一句话）

> **给普通人的每日 GitHub 实用项目日报**——别人推荐"开发者觉得酷"的项目，这里推荐"普通人真能用上"的工具，并且每天自动更新、同一项目 30 天不重复。

三句话展开：

- 对**读者**：一个每天打开就能看的中文网页，告诉他今天有什么能改善学习/生活/效率/健康/财务的新工具。
- 对**开发者**：一个零依赖、可自托管、可配置的日报生成引擎，可按需接 AI 润色。
- 与竞品的差异：HelloGitHub/GitHubDaily 是**人工精选、面向开发者**；本项目是**自动更新、面向普通人**，且"仓库是引擎、Pages 是产品"双形态。

### 1.2 目标用户（按优先级）

| 优先级 | 人群 | 他们的问题 | 触达渠道（仅可访问平台） |
|---|---|---|---|
| P0 核心 | **想用工具改善生活但不写代码的人** | 不知道有什么好工具，也看不懂技术社区 | 小红书、知乎、即刻、少数派 |
| P1 次核心 | **效率爱好者 / 自托管玩家** | 想要可掌控、可定制的信息源 | 掘金、知乎（技术话题）、少数派 |
| P2 扩展 | **内容创作者 / 资讯号** | 缺稳定的选题素材 | 知乎、即刻、小红书 |

> 中文单线下，五个平台分工：**少数派/掘金/知乎**做长文拉信任与星标，**小红书/即刻**做短内容拉访问与传播。长文里放仓库和 Demo 链接，短内容正文不放外链（引流到主页），分工不要混。
>
> HelloGitHub 通过 GitHub Issue 投稿（你能正常访问 GitHub），作为权威背书的补充渠道保留。

### 1.3 核心卖点（对外统一口径，三句话背下来）

1. **视角唯一**：专注"对普通人有用"，而不是"技术上很酷"——这是和所有竞品最大的不同。
2. **零门槛 + 可持续**：有在线日报每天自动更新（打开网页就能看），也有零依赖脚本可自己跑；30 天去重、领域配额避免刷屏。
3. **透明可控**：纯 Python 标准库、MIT 许可、可选 AI 且默认关闭、数据只存本地不上传。

**禁用话术**：不要说"保证每天 10 个精品"（项目定位是宁缺毋滥）、不要主动求 star（把"愿意试用/提 issue"放前面）。

## 4. 社区传播（让传播可持续，而非一次性）

- **作者在场**：每个平台发布后的前 24 小时，尽量回复每一条评论。早期项目的"作者亲自回复"比文案本身更能建立信任。
- **回答而不是硬推**：在知乎相关问题下，先给出有价值的回答，自然带出项目；不要在不相干群里丢链接。
- **借势同类项目**：在 HelloGitHub、GitHubDaily 的投稿/推荐渠道投自己；关注"每日开源"类账号的转载机制。
- **给贡献者台阶**：README 已有 CONTRIBUTING，推广时主动说"欢迎提 issue 说你想要监测哪些关键词"——把读者变成参与者，星标和讨论会自然增长。
- **不做的四件事**（红线）：不买星、不刷榜、不群发广告、不同一天全网铺同一段话。

## 5. 用户反馈收集（把流量变成产品力）

1. **入口**：Discussions 已开启，README 的 FAQ 下有引导。
2. **主动问**：每篇发布文案结尾统一放一个具体问题，例如"你最希望每天看到哪类工具？"——比"欢迎反馈"有效得多。
3. **归类**：每周把反馈分三类记到 `docs/FEEDBACK_LOG.md`：`质量误报` / `功能请求` / `使用困难`。质量误报优先修（这是产品生命线）。
4. **闭环**：修复后在该 issue/discussion 回复"已修复，感谢"，并考虑发布小版本 Release。被采纳的建议要公开致谢——这是最好的口碑素材。
5. **隐私**：反馈里若有人贴 token，立即提醒删除；不要在公开回复里引用任何凭据。

## 8. 三个月目标（可衡量）

- **Star**：0 → 200+（主要来自少数派 / 掘金 / HelloGitHub 三次首发）
- **Pages 月访问**：建立统计基线后稳步增长
- **真实反馈**：Discussions + Issue 累计 20+ 条，其中至少 5 条转化为改进
- **内容资产**：沉淀 4 周日更模板，形成可持续的内容飞轮

> 数字是方向不是承诺。如果某个平台明显无效（发了没人看），按数据停掉，把时间投给有效的那个——这比"每个平台都发一遍"更重要。
